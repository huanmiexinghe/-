# 磁极冲刺 · 联机模式部署说明

> 架构：**本地权威 + WebSocket 中转**。服务器只转发房间消息（建房/加入/选关/准备/开始/实时状态/完赛），不跑游戏逻辑；各玩家手机本地跑物理，15Hz 互发位置状态，渲染对方为半透明残影。

---

已改用 **cpolar HTTP 隧道**打通（不再使用 SakuraFrp），联机大厅保持"只输房间码"模式。

| 隧道类型 | **HTTP 隧道**（原生支持 WebSocket 升级，无需自建 TLS） |
| 本地地址 | **http://localhost:8080**（云电脑上 relay-server 监听） |
| 隧道公网地址（HTTPS） | **https://b181a8e.r28.cpolar.top** |
| **对外连接地址（WebSocket）** | **wss://b181a8e.r28.cpolar.top**（443 标准端口，不用写端口号） |

## 一、文件清单

| 文件 | 作用 |
|------|------|
| `server/relay-server.mjs` | 中转服务器主程序（Node.js，唯一依赖 `ws`）；自动探测 cpolar 并打印公网 wss 地址 |
| `server/package.json` | 服务器依赖声明与启动脚本 |
| `server/magnetic-rush-server.zip` | 上述两个部署文件的打包（上传云电脑用） |
| `server/start-with-tunnel.ps1` | Windows 一键启动（服务器 + cpolar 隧道，**主用方式**） |
| `server/start-with-tunnel.sh` | Linux 一键启动（同上，**主用方式**） |
| `src/net/OnlineManager.ts` | 客户端 WebSocket 单例，含 `DEFAULT_SERVER_URL` 常量 |
| `src/scenes/OnlineLobbyScene.ts` | 联机大厅界面（连接/房间/选关/准备）；地址栏自动识别 `https://`→`wss://` |
| `src/scenes/GameScene.ts` | ONLINE 模式：倒计时、状态同步、残影、实时排名 |
| `android/.../AndroidManifest.xml` | 已加 `android:usesCleartextTraffic="true"`（兼容局域网 ws:// 明文；wss 不受影响） |

服务器端口：默认 **8080**（环境变量 `PORT` 可改，但必须与 cpolar 隧道本地端口一致）。房间上限 4 人，房间码 6 位字母数字（如 `K7M2PX`）。

## 三、云电脑部署（cpolar，无公网 IP）

需要在云电脑上跑两件事：**① relay-server（8080）② cpolar 隧道（http 8080）**。

### 3.1 安装 cpolar 并绑定账号（一次性）

1. 到 https://www.cpolar.com/download 下载对应系统版本并安装（Windows 一路下一步；Linux 用官方一键脚本或下载 deb/rpm 包）。
2. 注册/登录 cpolar 后台 https://dashboard.cpolar.com/auth ，复制自己的 **Authtoken**。
3. 云电脑上执行一次（只需一次，会写入本地配置）：

```bash
cpolar authtoken <你的Authtoken>
```

### 3.2 启动（两件事）

**方式 A：一键脚本（推荐）**

```powershell
# Windows：右键 start-with-tunnel.ps1 → 使用 PowerShell 运行
cd server
.\start-with-tunnel.ps1
```

```bash
# Linux：
cd server
chmod +x start-with-tunnel.sh
./start-with-tunnel.sh
```

脚本会先后拉起 relay-server 和 `cpolar http 8080`，两个窗口/进程都保持开启即保持联机。

**方式 B：手动开两个窗口**

```bash
# 窗口①：中转服务器（端口必须 8080，与隧道本地端口一致）
cd server && npm install && npm start

# 窗口②：cpolar 隧道
cpolar http 8080
```

### 3.3 查公网地址

cpolar 启动后，relay-server 会自动探测本地 4040 API 并打印：

```
[relay] 已识别 cpolar 隧道，玩家服务器地址填：wss://b181a8e.r28.cpolar.top
```

也可以直接看：

- **cpolar 窗口**界面里的 `Forwarding  https://xxxxx.xx.cpolar.top -> http://localhost:8080`；
- 或浏览器开 http://127.0.0.1:4040 （cpolar 本地面板）。

把显示的 `https://` 地址换成 `wss://` 就是玩家连接地址（当前为 **wss://b181a8e.r28.cpolar.top**）。

## 四、验证链路是否打通

两件事都启动后，在任意联网电脑执行：

```powershell
# ① TCP/TLS 层：能连上 cpolar 边缘 443
Test-NetConnection b181a8e.r28.cpolar.top -Port 443
```

| 结果 | 含义 |
|------|------|
| `TcpTestSucceeded : True` | 已到达 cpolar 边缘，继续做 ② |
| `TcpTestSucceeded : False` | 本机网络问题或 cpolar 未启动 |

```powershell
# ② HTTP 层：请求公网地址，只要不是 cpolar 的 502/离线错误页，就说明已转发到 relay
Invoke-WebRequest https://b181a8e.r28.cpolar.top -UseBasicParsing
```

- 返回 **400 / 426**（WebSocket 服务拒绝普通 HTTP 请求）→ **链路完全正常**；
- 返回 **502 Bad Gateway / 503** → cpolar 在线但云电脑的 relay-server 没跑或没监听 8080；
- 浏览器直接打开该地址显示 cpolar **离线/错误提示页** → 隧道没启动。

最终确认：装 APK 进「联机竞速」，房主建房成功、其他人能凭 6 位房间码加入。云电脑 relay 控制台应能看到 `[relay] 新连接（当前 N 个）`、`[relay] 建房 XXXXXX`、`[relay] 玩家 加入 XXXXXX` 等日志。

## 五、域名：随机版 vs 预留版（重要）

| | 免费版随机域名（当前） | 付费预留域名 |
|---|---|---|
| 形态 | `b181a8e.r28.cpolar.top` | `你起的名字.cpolar.top`（后台"预留 → 保留域名"领取） |
| 重启 cpolar | **域名会变** | 固定不变 |
| 用法 | `cpolar http 8080` | `cpolar http -subdomain=你起的名字 8080`（具体参数以后台预留页提示为准） |
| 对客户端影响 | 每次变化都要改 `DEFAULT_SERVER_URL` 重新出包 | 出一次包永久用 |

临时玩几局用随机域名即可；固定车队长期联机强烈建议上预留域名，一劳永逸。

域名临时变了又来不及出包时：玩家可点大厅右下角"使用自建服务器 ›"，手动粘贴新的 `wss://xxx.cpolar.top` 地址（地址会被记住，只需填一次）。

## 六、DEFAULT_SERVER_URL（控制大厅形态）

`src/net/OnlineManager.ts` 顶部：

```ts
export const DEFAULT_SERVER_URL: string = 'wss://b181a8e.r28.cpolar.top';
```

| DEFAULT_SERVER_URL | 联机大厅界面 |
|--------------------|--------------|
| 空 `''` | 完整模式：服务器地址 + 昵称 + 房间码（地址会记住，只需填一次） |
| 已填写（当前） | **简化模式：只需昵称 + 6 位房间码**；右下角保留"使用自建服务器 ›"入口 |

换域名后改这一行，重新出包分发给玩家即可。注意 cpolar 是 **wss://**（带 TLS，443 端口），不要写成 ws://，也不要带端口号。

**注意**：这里必须写 `: string` 类型标注。若写成字面量类型，`OnlineLobbyScene.ts` 里的 `DEFAULT_SERVER_URL === ''` 比较会因类型无重叠而报 TS2367 编译错误。

## 七、重新出包流程

```powershell
cd D:\magnetic-rush-mobile
npx tsc --noEmit          # 类型检查
npx vite build            # 构建 web 资源
npx cap sync android      # 同步到 Android 工程

# 构建前处理 gradle 镜像冲突（BMCLAPI 会导致 cordova 解析失败）
Rename-Item "$env:USERPROFILE\.gradle\init.gradle" "init.gradle.bak"
Remove-Item "$env:USERPROFILE\.gradle\caches\modules-2\files-2.1\org.apache.cordova" -Recurse -Force

cd android
.\gradlew assembleDebug

# 构建后恢复
Rename-Item "$env:USERPROFILE\.gradle\init.gradle.bak" "init.gradle"
```

产物：`android\app\build\outputs\apk\debug\app-debug.apk`（文件名保持不变）

## 八、云电脑后台常驻（Linux）

```bash
# 安装 Node.js（Ubuntu/Debian）
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo bash -
sudo apt install -y nodejs

# 部署 relay
cd ~/server && npm install

# pm2 常驻 relay（崩溃自重启 + 开机自启）
npm install -g pm2
pm2 start relay-server.mjs --name magnetic-rush
pm2 save && pm2 startup

# cpolar 常驻为系统服务（authtoken 已配置的前提下）
cpolar service install
cpolar service start
```

用系统服务方式跑固定隧道时，在 cpolar 配置文件（Linux 默认 `/usr/local/etc/cpolar/cpolar.yml`，Windows 在 `C:\Users\<用户名>\.cpolar\cpolar.yml`）里声明：

```yaml
authtoken: <你的Authtoken>
tunnels:
  magnetic-rush:
    proto: http
    addr: "8080"
```

之后 `cpolar start magnetic-rush` 即按配置启动；relay 已内置 cpolar 探测，谁先启动都不影响，隧道上线后控制台自动打印 wss 地址。

## 九、常见问题

| 问题 | 原因 / 解决 |
|------|-------------|
| 连接失败 / 超时 | cpolar 没启动；relay-server 没跑；隧道本地端口不是 8080；云电脑防火墙拦了本地 8080 |
| 公网地址打开是 502 | cpolar 隧道在线，但转发不到本地服务——检查 relay 是否在 8080 运行 |
| wss 连不上 | cpolar 必须用 **HTTP 隧道**（`cpolar http 8080`）；确认客户端地址以 `wss://` 开头、不带端口号 |
| ws/wss 搞混 | 公网走 cpolar = **wss**（加密，443）；同一 WiFi 局域网直连 = **ws://IP:8080**（明文） |
| 昨天能连今天连不上 | 免费版随机域名重启后变了：看 cpolar 窗口/relay 控制台的新地址，手动填或改常量重新出包 |
| 房间码输不进去 | 房间码是**字母+数字混合**，客户端已支持字母并自动大写 |
| 建房/加入后卡住不跳页 | 已修复：`created`/`joined` 到达即切房间页；协议自动按地址补全 |
| 提示"比赛已经开始" | 该房间正在比赛中，等房主点"结束比赛·全体返回大厅" |
| 房主退了 | 房间不解散，房主自动转让给下一位玩家 |
| 远程联机卡顿 | cpolar 免费节点带宽/区域质量问题，可换就近区域或升级套餐；游戏逻辑在本地跑，只影响残影平滑度 |
| 想彻底不换地址 | cpolar 后台预留固定域名，用 `cpolar http -subdomain=xxx 8080` 启动 |
