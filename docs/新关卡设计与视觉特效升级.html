锯齿三：危险计数虚高，决策密度并不高

291 个致命障碍里有大量“同一决策”的双色尖刺、同屏上下刺。玩家实际面对的是“跳一次/定一次色”，不是 291 次独立判断。新关卡应按 决策组 计密度，而不是继续堆尖刺。

成对尖刺 = 1 个决策上下同屏 = 1 个决策锁门 = 1 个定色决策

锯齿四：关卡底色被天空完全盖掉

GameScene.renderBackground() 先 clear(level.bg)，随后 drawToonSky() 用不透明三段渐变铺满 960×540。结果：36 关的 bg 字段实际不可见，所有关共享同一片亮天空。这是“太平”的第一因，也是最便宜的修复点。

锯齿五：特效是“事件型”，没有持续层

现有粒子、震屏、闪白都只在事件发生后 0.2–0.5s 内出现；正常跑动时没有任何持续的速度层。加速时只有 boostStreak 每 50ms 冒一个白点，撑不起“越来越快”的体感。

由此得到的三个设计判断

1. 新关不需要把危险物数量翻倍，需要把“同一屏里的独立决策”变多。2. ★3 目标应贴近强制连击源，而不是被可选晶片淹没。3. 视觉升级必须先解决“每关看起来一样”，再谈粒子与光效。

第 8 章 · 代价之门（37–42）

机制主题：约束与取舍。不新增机制，只重新组合锁、诱饵、磁极镜、相位墙与平台。玩家的新问题是“我现在要不要花掉换色权”。

锁：定色后不能补救饵：+2 连击换 1.2s 锁 镜：强制翻转，考预判章末考试 L42

三层变奏：37 只教锁 → 38 加诱饵 → 39 加镜 → 40 加路线 → 41 锁镜饵连算 → 42 三种代价同屏。每一关只增加一种“代价”，不叠加新动词。

第 9 章 · 动量边境（43–48）

机制主题：动量与空间。弹射板、加速带、传送带、断桥、传送门、重力翻转。玩家的新问题是“我什么时候把速度/落点/重力交出去”。

弹射：同色上高线加速：落点预算 238→475 传送：空间改写章末考试 L48

三层变奏：43 路线 → 44 时间 → 45 落点 → 46 空间 → 47 节拍 → 48 四段收束。断桥与加速必须成对出现，不做纯反应关。

单关节奏：呼吸段 / 挑战段 / 高潮段

每关长度 4600–7600px。呼吸段负责“读规则”，挑战段负责“用规则”，高潮段负责“在压力下用规则”。章末关高潮段可拉长，但不把呼吸段压到 0。

危险密度与最小安全间距（硬规则）

  • 1反应预算：320px = 1.0s，160px = 0.5s，96px = 0.3s。D4 起，两个独立致命决策之间 ≥240px；加速状态下翻倍（≥480px）。
  • 2同决策合并：同 x 的上下尖刺、双色尖刺、同屏“跳一次”的障碍组，算 1 个决策；地图与连击评估都按决策组算。
  • 3尖刺群：单组宽度 ≤128px；起跳前净空 ≥80px，落点后净空 ≥120px。超过 128px 必须拆组或改为浮台路线。
  • 4灰墙：高度 ≤64px；相邻柱边沿间距 ≥370px（沿用 levels.ts:1-8 的既有约定），除非有弹射板/加速带的明确解法。
  • 5相位墙：颜色需求必须提前 ≥320px 可见；锁/饵生效期间不得出现“无安全色”的相位墙。禁：锁后 400px 内接异色墙。
  • 6锁门：D4 起宽度 ≥96px（1x 速度 0.3s）；进锁前的定色窗口 ≥320px；锁内不得再叠新的颜色判断。
  • 7诱饵：每关 ≤2 个；放在相位墙前 320–480px 才能形成“贪连击 vs 保安全”的取舍；绝不能成为 ★2 全晶片的必选项。
  • 8激光：预警 0.8s，1x 速度下等于 256px；激光前后 256px 不放新的颜色决策；加速状态下周期必须 ≥3.2s，否则只保留带地面安全缝的垂直激光。
  • 9摆锤：水平危险半径约 ±151px（绳 260×sin35°），预警提前量 0.45s ≈144px；同屏第二个摆锤 ≥600px；摆锤充能圈内不放新的换色决策。
  • 10断桥：宽度只允许 180 / 240 / 300 三档。240 需要贴边起跳，300 必须有 ≥1.8x 加速源或弹射板；落点后 ≥160px 不得接尖刺。
2B

组合范式：哪些机制放在一起会产生“新决策”

判断标准只有一句：玩家是否需要在看到 A 时，为 B 提前做选择。只是“多了一个障碍”不算组合范式。

PARADIGM 01

约束换色

锁 / 诱饵 + 相位墙

新决策：进锁前把颜色定对；诱饵要不要吃。

例子：L38 诱饵 1400 → 相位墙 1800；取饵后 1.2s 不能换色，当前色不对就必须放弃 +2。

禁止：锁后 400px 内接异色墙，且没有安全色可提前选择。
PARADIGM 02

颜色预判

磁极镜 + 相位墙

新决策：不是“镜后反应”，而是“进镜前预切”。镜会强制翻转，玩家要倒推入口颜色。

例子：L39 镜 1200 → 红墙 1500；想以红出镜，就要以蓝进镜。

禁止：镜后墙距 <240px，只剩纯反应，失去预判价值。
PARADIGM 03

路线投资

弹射板 / 高台 + 磁芯

新决策：同色上高线拿磁芯，异色走低线保安全；两条都能通关，收益不同。

例子：L40 高线 3 枚磁芯（不计 ★2），低线 6 枚晶片保 ★2；L43 红板走高台，蓝板走地面。

禁止：高线磁芯计入 ★2 全晶片，否则路线选择变成“必须跳”。
PARADIGM 04

动量承诺

加速带 / 传送带 + 断桥 + 落点

新决策：加速把跳跃水平位移从 237.7px 拉到约 475px；起跳点必须提前，落点变宽也变险。

例子：L45 4500 加速 → 5000 的 300px 断桥；跳早会落进桥，跳晚过不去。

禁止：加速窗口内引入第一次出现的新颜色机制。
PARADIGM 05

空间改写

传送门 + 重力翻转 + 移动浮台

新决策：同一段路出现“地面线”和“天花板线”，选哪条、何时进传送门。

例子：L46 地面门 1600 → 天花板 1800，浮台 2300 横移，4200 再回地面。

禁止：传送门出口 120px 内接致命物；出口必须先给一个可读的落点。
PARADIGM 06

节拍合流

摆锤 / 激光 + 相位墙

新决策：在摆锤的安全窗口内完成换色，而不是等摆锤过了再想颜色。

例子：L47 1800 摆锤 → 2600 蓝墙；4200 蓝摆锤 → 4600 锁 → 5000 蓝墙。

禁止：摆锤充能圈与相位墙同屏重叠；两件事必须能分开读。

为什么做 37–48，而不是重做 31–36

1. 31–36 刚调过，且已有节奏任务在排队。L36 的源余量只有 1，重做很容易把 ★3 从“紧”变成“不可能”。2. 新增关不动存档结构与解锁逻辑。LEVELS.length 已被成就与关卡选择动态引用；新增 12 关只会让网格多滚两行，不需要迁移旧存档。3. 新设计语言需要“从零教一次”。37 可以把锁门单独教干净；在 31–36 中间插教学会打断现有 7 章节奏。4. 31–36 的主题是“边境装置”，37–48 是“代价/动量”，两章并列更清楚。

零存档迁移不动 31–36 星标可与节奏任务并行

如果之后仍要重做 31–36

优先动 L31–33（余量 11 / 9 / 5），把 ★3 目标抬到“强制源覆盖”的水平；L34 可加一条可选高线；L36 只做“减负”不做“加难”，因为它的余量已经只有 1。不要在这份设计稿里同时改 31–36，避免和正在进行的关卡节奏任务冲突。

先 31–33L36 只减负不与本稿混做

反模式：这些做法只会“看起来更难”

双威胁同窗：240px 内同时要求换色和跳跃，玩家只能靠背板。颜色决策与跳跃决策至少隔 240px。
饿死式连击：★3 目标 = 全部源（如 L24 的 13/13），零容错会把“掌握”变成“背谱”。
必选诱饵：把诱饵放进 ★2 全晶片路径，等于没有取舍——吃饵固定给 +2 连击并锁色 1.2s（MECH.BAIT.switchLock），玩家只剩“被迫换一次色”，谈不上决策。
加速后教新机制：2x 速度下反应窗只剩一半，第一次出现的颜色/锁必须放在 1x 段。
断桥后立即落刺：落点后 <160px 接尖刺，失败原因会变成“看不见”，不是“跳错”。
摆锤叠相位墙：充能圈、摆锤实体、墙色三者同屏，信息过载且不公平。
粒子盖危险：在尖刺/相位墙上加高亮粒子或全屏闪，直接破坏红蓝语法。
锁 + 异色墙无解：锁生效期间墙色与当前色不符，且没有提前定色窗口，属于无解关。
03

12 个新关：37–48

选择“在 36 关之后新增”而不是“重做 31–36”：不碰现有星标、存档与 31–36 的节奏调整，同时给新设计语言一个完整的教学章。每关都给出机制组合、关键节奏点、难度定位、连击源估算、预计时长与侧视示意图。

第 8 章 · 代价之门（37–42）

章节目标：让玩家学会“换色权是一种资源”。锁让你不能改，诱饵让你不想改，镜让你必须提前改。三个机制都已在仓库里，本章只改变它们的排列方式。

锁门磁芯诱饵磁极镜相位墙

第 9 章 · 动量边境（43–48）

章节目标：让玩家学会“提前承诺”。弹射板决定高度，加速带决定落点，传送带决定时间，传送门/重力翻转决定空间。所有 300px 断桥都有明确加速源，不做无解反应。

弹射板加速/传送带传送门/重力断桥

曲线是 37–48 的设计目标，不是实测。竖轴同时叠了“危险密度（致命障碍 / 1000px）”与“连击源密度（源 / 1000px）”；柱状为 ★3 目标占全部连击源的比例，用来检查有没有把 ★3 写成“全收集”。D 档区间用底色标出，章末 L42/L48 允许冲到 D4.5/D5，但必须是四段式分区，不是全关堆叠。

实装顺序建议

先做 37（验证锁门教学）与 38（验证诱饵取舍），再用 43 验证“颜色选路线”，最后做 48 收束。每加一关都跑 countComboSources 与可达性自检，再批量补 39–42、44–47。

数据落点

新关只进 src/data/levels.ts 的 LEVELS 数组，沿用 spike/wall/pwall/lock/bait/mirror/pend/laser/plat/mplat/portal/flip/boost/conv/pit/pad/gem/currency/finish 等现有 helper；不新增 Obstacle 种类。

不做什么

不把 37–48 写成“障碍大杂烩”。每关只允许 1 个主机制 + 1 个旧机制复现；章末 L42/L48 才允许三机制同屏，且必须按四段分区，不允许全关随机堆叠。

为什么“特效不少，但还是平”

1. 没有持续层。所有特效都在事件后 0.2–0.6s 内消失，正常跑动时画面是静止的。2. 没有章节差异。天空、色温、云都一样，关卡只剩障碍排列不同。3. 没有时间反馈。死亡/受击没有顿帧，换色没有短暂“世界被改写”的感觉。4. 特效位置不对。粒子画在危险物之上，越多越糊；真正该动的背景层反而空着。

升级前必须守住的三条

红蓝语法：红/蓝是危险与极性的唯一语法，不允许加色相偏移、泛光或色差让它们变紫/变白。中心留白：屏幕中央 60% 是读危险区，只允许边缘色洗，不允许全屏闪。同屏一件事：换色、收集、连击爆发、震屏不要在同一帧同时触发；否则玩家只会感到“吵”。

05

视觉升级方案：在现有 Canvas 2D 管线里做

分三档：立即能做、中等成本、高成本。每项都写清现状、改法、代码落点、性能开销与可读性影响。性能数字是估算，不是实机 profile。

先明确预算

逻辑画布 960×540；移动端 DPR 上限 1.5（Renderer.ts:37-41），实际约 1440×810 = 116 万像素。60fps 每帧 16.6ms，建议新增特效总预算：中端安卓 <4ms，低端 <2ms。现有粒子池上限 600（ParticleSystem.ts:19），新特效优先复用池或独立小池，不在每帧 new 对象。

立即：0.1–0.5ms / 项中等：0.5–2ms / 项高：2–8ms / 项不做全屏 filter
I1

关卡氛围：把被天空吃掉的 level.bg 救回来

立即可读性安全
现状

renderBackground() 先 clear level.bg，再让 drawToonSky() 不透明铺满；36 关天空完全一样。

改成

天空之后叠一层 level.bg（multiply 或 source-over，透明度 8–12%）；再给 31–48 两套章节调色板（暖黄昏/冷夜色），云的 x 随相机做 0.06/0.12 视差。

落点

GameScene.ts:1833-1869；widgets.ts:117-211。只改背景层，不动障碍绘制。

成本

1 个全屏 rect + 1 次 blend，≈0.2ms；无新对象。

可读性

安全：背景在障碍之前绘制，红蓝不被染色；透明度 ≤12%，只影响天空/远景。

验收

同一关开关特效截图对比，障碍像素颜色不得变化。

I2

速度感：速度线 + 相机前瞻 + 角色前倾

立即需护栏
现状

加速只有 boostStreak 每 50ms 一个白点；相机固定 0.35 偏移；角色没有前倾/拉伸。

改成

加速或 speed≥500 时，在世界层画 8–12 条低对比速度线（背景后、障碍前）；相机目标加 min(speed-320,320)*0.10（2x 时 +32px）；角色按速度旋转 2–3°、scaleX 1.03；加速开始触发一次 1.2px/0.12s 轻震。

落点

GameScene.updateCamera() 1731-1736；GameScene.render() 1762-1805；Player.drawRunner() 30-99；ParticleSystem.boostStreak() 127-134。

成本

8 条 stroke + 1 次 transform，≈0.2–0.3ms；不新增粒子。

可读性

需护栏：速度线只画在背景层、alpha≤0.25；不在正常速度下出现；轻震只在加速起步一次，禁止连续抖动，尊重现有 shake 开关。

验收

2x 速度下速度线可感知，但尖刺/墙的轮廓与颜色不变。

I3

换色反馈：边缘色洗 + 两道残影

立即可读性安全
现状

只有一个 4→80 的扩散环（0.3s）；换色是核心动词，但画面只“叮”一下。

改成

保留环；加 0.12s 四边内向色洗（极性色，alpha 0.10，中心 60% 不覆盖）；玩家身后画 2 个反向极性残影（x-8/-16、alpha 0.16）；顶部极性胶囊同步 pulse 1.08 倍 0.15s。

落点

GameScene.ts:1145-1153 换色分支；1803-1805 玩家绘制前；HUD 1960-1974；ParticleSystem.switchRing() 62-67。

成本

2 次角色绘制 + 4 条边渐变，≈0.15ms；只发生在换色帧。

可读性

安全：中心不遮；残影在玩家身后 16px 内、alpha≤0.2；不改变碰撞与判定。

验收

连续快速换色不出现残影堆积（残影只保留最近 2 个）。

I4

收集反馈：磁吸轨迹 + +1 数字 + HUD 脉冲

立即需护栏
现状

9 个火花 + 扩散环 + 音效 + 连击；玩家只知道“收到了”，不知道“收到了什么/多少”。

改成

未收集晶片在玩家前方 120px 内时画一条 2px 金色磁吸虚线（视觉偏移，不移动判定体）；收集时在玩家上方弹 +1（0.45s，最多 6 个）；右上晶片计数做 1.15 倍脉冲 0.15s。

落点

GameScene.ts:1529-1543 收集分支；HUD 1992-1998；ParticleSystem.sparks() 70-81。数字可用独立小数组，不扩 ParticleSystem。

成本

最多 6 个 text + 3 条线 + 原有 9 粒子，≈0.4ms。

可读性

需护栏：数字只在玩家上方 40px，不进入障碍命中区；同屏最多 6 个；0.45s 必淡出。

验收

连吃 10 枚晶片不出现数字叠成一团；HUD 不抖动布局。

I5

死亡反馈：60ms 顿帧 + 碎片 + 红晕

立即终端反馈
现状

12 个三角碎片、震屏 6/10、0.4 白闪、0.5s 红色叠层；没有顿帧，死亡像“画面切了一下”。

改成

离线模式死亡瞬间跳过 60ms 的 update（仍 render）；碎片 12→20、加 6 条从撞击点放射的短线；白闪降到 0.12，红晕只压边缘；相机轻推 2px 后回中。

落点

Game.ts:86-99 主循环；GameScene.die() 829-844；render 1822-1829；ParticleSystem.deathBurst() 84-97。

成本

20 碎片 + 6 线 ≈0.2ms；顿帧不增加渲染成本。

可读性

安全（死亡是终局）；但白闪 ≤0.12、不频闪、不做全屏红；联机模式禁止顿帧，避免与服务端时间不同步。

验收

死亡手感明显变“重”，且不会让玩家误以为还能操作。

I6

UI 动效：星级逐个弹出 + HUD 里程碑

立即可读性安全
现状

结算卡有 pop，但三颗星和卡片一起出现；关卡选择/菜单无转场；HUD 连击数字是静态文本。

改成

三星按 0/1/2 顺序，每颗延迟 0.10s，0.8→1.12→1 的 0.22s 弹跳；连击跨 10/20/30 时数字放大 1.12 倍 0.15s；关卡选择卡片 hover 上浮 2px。

落点

ResultScene.drawStars() 272-277（需传入时间）；GameScene HUD 1933-1958；LevelSelectScene 格子绘制。

成本

每帧多 2–4 个 transform，≈0.05ms。

可读性

安全：只在结算/HUD，不进入跑动视野。

验收

星级弹出不遮挡“下一关”按钮；键盘操作不受影响。

05B

中等与高成本：把“事件特效”变成“持续世界”

立即档解决“有没有反馈”；这一档解决“关卡之间有没有区别、跑动时画面会不会动”。所有实现仍只用 CanvasRenderingContext2D，不引入 WebGL、不引入第三方后期库。

这一档的共同前提

中等档的每一项都必须回答一个问题：它是否每帧都在动？如果答案是否，它就不该放在这一档，而应回到 I 档做一次性事件。高成本档则必须回答：它是否动了“世界层”的像素？只有背景、地面、光、残影允许动；障碍本体、碰撞判定区、HUD 数字区一律不动。

中等：持续层高：世界层都不碰危险物像素
M1

分层视差 + 章节天空：让 36+12 关不再长得一样

中等可读性安全
现状

drawToonSky() 一条渐变走天下；云按 time 漂移；草地固定 0.6 视差；level.bg 被覆盖（见 I1）。

改成

把背景拆成三层：远山/天光（视差 0.05）、云（0.12）、近景剪影（0.35，压在地面线下方）。为第 8 章“代价之门”配暖黄昏（#ffd9a8→#ff9f8a），第 9 章“动量边境”配冷夜（#a9c9ff→#2b3a66）；章节内每关只微调 ±6% 明度，不再逐关换色。

落点

widgets.ts:117-211 新增 drawChapterSky(ctx, chapter, camX, t)；GameScene.renderBackground() 1833-1869 改为按 level.chapter 取调色板。云/山用现有 toonShape，不新增资源。

成本

每帧 3 层约 10–16 个填充图形，≈0.6–1.0ms；移动端可用每 2 帧更新一次的静态层缓存。

可读性

安全：全部在障碍之前绘制；近景剪影只出现在地面线以下 40px，不进入跳跃判定区；章节色调只作用于天空，不给障碍叠色。

验收

截取 L38 与 L44 同机位截图，天空/远景必须一眼可区分；尖刺 RGB 值不变。

M2

危险地面贴片：把“危险在哪”提前画在地上

中等提升可读性
现状

尖刺、激光、断桥只画本体；障碍预告靠颜色与闪烁，玩家在高速下要先“看见物体”才判断落点。

改成

在每个致命障碍的地面投影位置画一块 12px 高的半透明贴片（红/蓝对应极性，alpha 0.18），并沿前进方向画一条 40px 的渐隐引导线；断桥画 3 段虚线跨越缺口；激光在地面画横向刻度。贴片只画在 y ≥ 430 的地带。

落点

GameScene.render() 1762-1805 障碍绘制循环内、Obstacle.render() 之前插一层 drawDangerGuides()；数据从 obstacles 的 kind/x/w 直接读取，不改 Obstacle 类。

成本

同屏约 8–14 个 rect/虚线，≈0.5–0.8ms；纯填充，无阴影无模糊。

可读性

正向提升：贴片在地面，不覆盖障碍本体；alpha ≤0.2，不能比尖刺更亮；红蓝必须与障碍同色，禁止用黄色“统一警告色”。

验收

高速段盲测：玩家能在障碍进入屏幕前 0.3s 指出“要跳还是换色”。

M3

连击的持续层：HUD 连击条 + 屏幕边缘热度

中等需护栏
现状

连击只有 HUD 胶囊里的数字与 comboBurst 的瞬时爆发；连击高低不影响画面，玩家感受不到“我正在滚雪球”。

改成

combo / maxCombo 映射到 0–1 的“热度”：HUD 胶囊下加一条 3px 进度条；屏幕四角画 4 段向内渐隐的极性色晕（alpha 0.04–0.12），连击 ≥50 时晕色走 rainbow() 但饱和度压到 35%。

落点

GameScene HUD 1928-2058 新增连击条；render 1822-1829 的 flash 层旁边新增一个 drawComboHeat()；复用 utils/Color.rainbow()。

成本

4 个角渐变 + 1 条 rect，≈0.3–0.5ms；只在 combo≥5 时绘制。

可读性

需护栏：色晕只贴四角，中心 60% 透明度为 0；连击断掉时 0.2s 内淡出，不允许残留；不与死亡红晕同时出现。

验收

连击 0→60 的过程中，障碍识别速度不下降；关闭特效开关后完全消失。

M4

低分辨率残影：不加 WebGL 也能做出“拖影”

中等需护栏
现状

轨迹是每 0.05s 一个小圆点（trail），玩家本体没有残影；2x 加速时“快”只体现在背景移动速度。

改成

用一个 1/4 分辨率离屏 canvas（240×135）保存上一帧的玩家/加速带区域，按 speed≥480 时以 alpha 0.18–0.28 拉伸回全屏叠一次；只在加速中与弹射后 0.4s 内启用。这个离屏层只画玩家与加速带，不画障碍，因此不会糊住危险物。

落点

新增 core/Afterimage.ts（约 60 行）；GameScene.render() 1762-1805 在玩家绘制后合成；ParticleSystem.boostStreak() 127-134 保留作为近景速度线。

成本

1 次 240×135 绘制 + 1 次全屏 drawImage，≈0.7–1.2ms；必须按条件启用，常驻会翻倍填充率。

可读性

需护栏：残影源层排除障碍与收集物；alpha ≤0.28；只向玩家身后偏移 6–10px，不向前瞻方向拖，避免“假障碍”；关闭 shake/特效时一并关闭。

验收

开/关残影各跑一次 L43，玩家能明确感到加速；尖刺边缘不得出现拖影。

M5

关卡转场 + 结算星轨：把“进入/离开”也做成反馈

中等可读性安全
现状

GameScene 进入即开局，ResultScene 只有卡片 pop；关卡选择点进去是硬切，缺少“开始跑”的仪式感。

改成

进场 0.45s：镜头从 cameraX-60 推到目标位，同时上下各压一条 24px 的章节色遮幅；结算时三颗星沿一条 0.6s 的弧线依次飞入（复用 drawStars 的坐标，不改判定）。

落点

GameScene 增加 introT 字段并在 update/render 使用；ResultScene.drawStars() 272-277 增加 t 参数；Scene 切换处无需改动。

成本

进场 0.45s 内每帧多 2 个 rect；星轨只在结算页，≈0.05ms。

可读性

安全：遮幅在屏幕最上/最下 24px，不进入跑动读区；开场 0.45s 内玩家不可操作，但也不放任何障碍进入屏幕。

验收

连续进出 10 次无卡顿；开场遮幅不遮挡第一枚晶片。

05C

高成本：只在“值得”的地方花

高成本项的共同点是占用填充率或改变像素合成方式。这里给三项，但建议只做 H1 与 H2；H3 留到有真机 profile 之后再决定。

H1

轻量世界光：径向光斑 + 章节天光（additive）

高需护栏
现状

世界没有光源概念，所有障碍是平涂 + 硬阴影；章节天空即使换了色，也像一张贴纸。

改成

在障碍之后、玩家之前，用 globalCompositeOperation='lighter' 画 1 个大径向渐变（屏幕上方 1/3，章节色）与最多 3 个小光斑（传送门/星核附近）；玩家脚下画一圈 0.5 强度的地面反光。

落点

GameScene.render() 1780-1795 障碍与玩家之间插 drawWorldLight()；渐变对象按章节预建并缓存，不在每帧 createRadialGradient。

成本

1 个大渐变 + 3 个小渐变 ≈1.5–3.0ms（移动端填充率敏感）；低端机可降到只保留大渐变。

可读性

需护栏：光只加在背景与地面，禁止覆盖尖刺/墙/激光；lighter 会让红色偏橙，必须把危险物绘制移到光层之后，保证红蓝原色。

验收

开灯前后取尖刺中心像素，色相偏移 <3°；帧时间不超过预算 +2ms。

H2

几何碎裂：用障碍真实轮廓生成死亡碎片

高终端反馈
现状

deathBurst() 固定 12 个三角，与撞击物无关；撞墙和撞刺看起来一样。

改成

死亡时读取撞击 Obstacle 的 kind/x/y/w/h，按类型生成 6–18 个碎片：尖刺→细长三角、墙→方块、激光→短线、断桥→长条。碎片速度按撞击方向加权，0.6s 内重力下落并淡出。

落点

ParticleSystem.deathBurst() 84-97 增加 shape 参数；GameScene.die() 829-844 传入撞击物；Obstacle 已有 x/y/w/h 可直接用。

成本

最多 18 个多边形 + 每帧变换，≈0.3–0.6ms；只在死亡帧之后的 0.6s。

可读性

安全（死亡即终局）；但碎片不得残留超过 0.7s，避免重生后误读为障碍。

验收

撞尖刺/撞墙/撞激光三种死亡，碎片形状可区分。

H3

章节天气层：雪 / 尘 / 电磁微粒

高慎用
现状

没有环境粒子；所有粒子都由事件触发。

改成

每章一套 60–90 个环境粒子（雪：慢速斜落；尘：水平漂移；电磁：随机短闪），独立小池，不复用战斗粒子池，避免抢占 600 上限。

落点

新增 core/AmbientLayer.ts；GameScene.renderBackground() 1833-1869 末尾调用；参数放 data/config.ts。

成本

60–90 个 1–2px 点，≈0.4–0.8ms；但会和背景层、光层叠加，低端机总成本易超。

可读性

慎用：环境粒子必须画在障碍之前，alpha ≤0.35，禁止进入屏幕中心 40% 区域；电磁短闪不得使用红/蓝纯色，避免与极性混淆。

验收

粒子密度最高的一关，玩家仍能在 0.25s 内识别第一枚尖刺。

H4

不做项：全屏径向模糊 / 色差 / Bloom

明确不做破坏可读性
为什么诱人

“速度感”最直觉的做法是全屏径向模糊；“受击”最直觉的是色差 + Bloom。看起来一步到位。

为什么不做

Canvas 2D 没有低成本全屏卷积；ctx.filter='blur()' 在移动端会触发软件回退，单帧可到 8–20ms。更关键的是：模糊会把 40px 宽的尖刺与背景混在一起，直接违背跑酷游戏的第一可读性原则。

替代

用 M4 的低分辨率残影做“速度”，用 I5 的顿帧 + H2 的几何碎片做“受击”，用 4 角色晕做“冲击”——都不碰危险物像素。

成本

省下的不是代码量，是低端机的整帧预算；这类效果一旦上线，通常要靠“特效开关”兜底，等于默认关闭。

可读性

不可接受：中心区模糊 = 危险物轮廓消失。

结论

如果未来真的迁到 WebGL，再单独评估；当前 Canvas 2D 管线不引入。

优先级与分批：先让玩家觉得“不一样”

排序依据不是“效果炫不炫”，而是三件事：覆盖频率（每关都看到 / 每秒都看到 / 每次失败才看到）、可读性风险、是否依赖新系统。先做覆盖频率最高且零风险的三项。

优先级项目覆盖频率改动量可读性风险为什么排这里
P0I1 关卡底色/章节天空每一关、每一秒XS无只改背景层，立刻解决“36 关长得一样”；是所有氛围项的地基。
P0I2 速度线 + 相机前瞻加速段 / 高速段S低跑酷的“快”必须有视觉证据；不改碰撞，只改取景与背景线。
P0I5 死亡顿帧 + 碎片每一次失败S无（终局）死亡是玩家停留时间最长的瞬间；顿帧是“手感”而非“特效”。
P1I4 收集磁吸 + 数字每 3–5 秒S低直接服务 ★2 全晶片目标，让“收集”从背景变成任务。
P1I3 换色边缘色洗 + 残影每次换色XS无换色是核心动词，当前反馈最轻；改动只在换色帧。
P1M1 分层视差 + 章节配色每一关、每一秒M无I1 的完整版；把“章节”真正做出来，而不是只换一层色。
P1M2 危险地面贴片每一个致命障碍M提升可读性唯一“加特效反而更安全”的项，优先级应高于任何光效。
P2I6 星级弹出 + HUD 里程碑结算 / 连击节点XS无低成本，但只在结算页出现；放在 P1 之后补。
P2M3 连击条 + 边缘热度连击≥5 时S低让 ★3 目标“看得见进度”；需要护栏，所以不做第一批。
P2M5 转场 + 星轨进/出关卡S无仪式感强，但不影响跑动体验；适合作为版本包装。
P3M4 低分辨率残影加速/弹射M需护栏观感提升大，但填率与“假障碍”风险需要真机验证。
P3H2 几何碎裂每一次失败M无（终局）I5 的完整版；先做 I5 验证顿帧，再升级碎片形状。
P3H1 世界光每一关、每一秒L需严格护栏氛围收益最高，但最容易把红蓝染偏；放在有特效开关之后。
不做H3 天气层 / H4 全屏模糊——高H3 需真机预算证明；H4 直接破坏危险物轮廓，不在 Canvas 2D 做。

Batch A · 地基（先做这一批）

I1 + I2 + I5
  • 目标：玩家第一眼能感到“每关不一样、加速更快、死亡更重”。
  • 内容：章节底色叠层；速度线 + 相机前瞻 + 角色微前倾；死亡 60ms 顿帧 + 白闪降到 0.12 + 红晕只压边缘。
  • 依赖：无。三项都不需要新系统、不需要新资源。
  • 验收：同一关开/关对比截图；障碍 RGB 不变；低端机帧时间增幅 <0.6ms。

Batch B · 反馈闭环

I3 + I4 + I6
  • 目标：把“换色 / 收集 / 结算”三个高频动作都给出明确回答。
  • 内容：换色边缘色洗与 2 个残影；晶片磁吸虚线 + +1 弹出 + HUD 脉冲；三星依次弹出、连击跨 10/20/30 放大。
  • 依赖：Batch A 的 UI 时间基准（introT / 结算 t）。
  • 验收：连吃 10 枚晶片数字不叠团；连续换色残影最多 2 个；★3 进度可读。

Batch C · 章节世界

M1 + M2 + M5
  • 目标：让第 8/9 章在视觉上成为两个世界，同时把危险预告做进地面。
  • 内容：三层视差 + 章节调色板；危险地面贴片与断桥虚线；进场 0.45s 遮幅 + 结算星轨。
  • 依赖：需要 LevelDef 上的 chapter 字段（当前 levels.ts 没有显式 chapter，可按 id 区间推导，不必改数据结构）。
  • 验收：L38/L44 同机位可区分；高速段盲测能提前 0.3s 指出“跳还是换色”。

Batch D · 高成本试验

M3 + M4 + H1 + H2
  • 目标：在真机上把“拖影/世界光/碎裂”跑通，再决定是否常驻。
  • 内容：连击条与四角色晕；1/4 分辨率残影；章节天光；按撞击物生成的几何碎片。
  • 依赖：必须先有统一特效开关（现有 ScreenShake.enabled 只覆盖震屏，需要扩成 fxLevel）。
  • 验收：低端安卓 60fps 不跌到 45 以下；尖刺色相偏移 <3°；关闭开关后画面回到 Batch A 基线。

明确不做什么

不做全屏后期链：项目没有 WebGL / 后期管线；Canvas 2D 的 ctx.filter 在移动端不可控。任何“加个 Bloom/色差/径向模糊”的方案都不落地。
不做粒子堆量：现有 MAX_PARTICLES=600，再堆只会让障碍变糊；新增特效优先用 transform、渐变、离屏小画布，不扩粒子池。
不在危险物上加光：尖刺、相位墙、激光、断桥本体禁止附加发光/粒子/色相偏移；发光只能出现在地面贴片与背景。
不做全屏闪：死亡白闪 ≤0.12、换色色洗 ≤0.10，且只压边缘；频闪既伤眼也破坏红蓝判断。
不做“每关一套专属特效”：12 关 × 专属特效 = 无法维护的素材债；只做章节级差异 + 机制级反馈。
不在联机模式加顿帧：联机以服务端时间为准，本地顿帧会造成位置插值跳变；I5/H2 只在离线模式启用。

怎么验证“真的变好了”

1. 像素基线：同一关同机位截图，取尖刺/相位墙中心像素，开特效前后 RGB 差 ≤ 6。2. 帧预算：中端安卓用 3 分钟连续跑，记录 p95 帧时间；Batch A ≤ +0.6ms，Batch B ≤ +1.2ms，Batch C ≤ +2.0ms，Batch D 单独评估。3. 盲测：让没玩过的人跑 L43/L47，记录“第一次看见尖刺到做出反应”的时间；M2 上线后应缩短。4. 回归：跑 npm run build 与项目自带 selfcheck，确认没有因新增绘制改变 countComboSources、星级判定与存档结构。
